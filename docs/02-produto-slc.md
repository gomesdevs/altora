# 02 — Produto SLC (Simple, Lovely and Complete)

## O que significa SLC

| Princípio | Na Altora |
|-----------|-----------|
| **Simple** | Uma narrativa única: "meu patrimônio alternativo, organizado e compreensível" |
| **Lovely** | Interface que transmite confiança institucional, não planilha com skin |
| **Complete** | Resolve o ciclo inteiro de gestão — da entrada ao relatório para o sócio |

**Complete** não significa "todas as features no lançamento". Significa:

> O usuário nunca precisa sair da Altora para entender, administrar ou reportar seu patrimônio alternativo.

Ele pode sair para **executar** (comprar na corretora, emitir na tokenizadora, assinar no cartório) — mas a **inteligência, governança e memória** ficam na Altora.

---

## Tese central

> A Altora é o sistema operacional do patrimônio alternativo brasileiro — o lugar onde imóveis físicos, FIIs, CRIs, participações societárias, private equity e créditos tokenizados passam a existir como um portfólio coerente, mensurável e governável.

## Os 5 pilares

### Pilar 1 — Patrimônio Unificado (fundação)

Ledger patrimonial único que agrega todos os ativos alternativos.

| Tipo de ativo | O que a Altora guarda |
|---------------|----------------------|
| Imóvel físico | Matrícula, SPE, vacância, aluguel, IPTU, avaliação, documentos |
| FII / Fiagro | Cota, proventos, segmento, administradora, concentração |
| CRI / CRA / debênture | Emissor, indexador, vencimento, fluxo de pagamentos |
| Participação societária | % capital, valuation, direitos, atas, dividendos |
| Private equity / VC | Commitment, capital calls, NAV, DPI/TVPI |
| Crédito tokenizado | Plataforma emissora, token, yield, status regulatório |

**Diferencial:** modelo de dados patrimonial que trata imóvel físico e FII como partes do mesmo universo.

---

### Pilar 2 — Inteligência Patrimonial (cérebro)

Transforma dados brutos em informação para decisão.

**Três níveis de atualização (honestos):**

1. **Tempo real** — FIIs, cotas listadas, alguns tokenizados com API
2. **Periódico** — avaliações de imóveis, NAV de fundos PE
3. **Event-driven** — capital call, vencimento de CRI, vacância reportada

**Métricas para alternativos:**

- Yield efetivo por ativo e classe
- Liquidez estrutural (30/90/365 dias)
- Concentração de risco (geográfica, emissor, estratégia)
- Vacância e ocupação
- Benchmark contextual (IFIX, INCC, CDI)
- Patrimônio líquido ajustado (descontando iliquidez e capital calls pendentes)

---

### Pilar 3 — Governança e Colaboração (confiança)

Infraestrutura para as pessoas que orbitam o patrimônio.

| Persona | O que vê | O que faz |
|---------|----------|-----------|
| Patriarca / titular | Tudo | Decide, aprova simulações |
| Filho / sucessor | Visão consolidada, sem docs sensíveis | Acompanha |
| CFO / controller | Fluxos, vencimentos, relatórios | Opera, reconcilia |
| Consultor / gestor | Portfólios dos clientes | Analisa, recomenda |
| Contador | Export fiscal e patrimonial | Declara, audita |
| Advogado | Documentos societários, contratos | Revisa estruturas |

**Funcionalidades:** trilha de auditoria, aprovações em duas etapas, comentários por ativo, alertas configuráveis, data room por operação.

---

### Pilar 4 — Reporting Institucional (profissionalismo)

Relatórios de nível family office — não export de planilha.

| Tipo | Uso |
|------|-----|
| Patrimonial mensal/trimestral | Visão executiva para sócios |
| Operacional | Vacância, inadimplência, vencimentos |
| Performance | TWR/MWR por classe, benchmarks |
| Fiscal | Bases para IR, ganho de capital |
| Regulatório | Estruturas CVM quando aplicável |
| White-label | Marca do consultor ou family office |

Relatório é **vista viva** com rastreabilidade: "este número veio desta fonte, atualizado em tal data".

---

### Pilar 5 — Ecossistema de Oportunidades (expansão natural)

Não é marketplace aberto no início. É **pipeline privado de oportunidades** integrado ao portfólio.

1. Oportunidade entra no sistema
2. Altora cruza com perfil patrimonial (ticket, geografia, concentração)
3. Simulador mostra impacto antes do compromisso
4. Interesse → data room privado com NDA
5. Decisão registrada na trilha de governança

**Tokenização na Altora SLC:**

- Assistente de estruturação (frações, custos, enquadramento CVM 88)
- Simulador de captação
- Checklist regulatório
- Integração pós-emissão (token entra no portfólio)
- Parceiros regulados emitem e distribuem

## Fluxo do usuário

1. **Entra** → vê patrimônio consolidado (momento "uau")
2. **Explora** → concentração, liquidez, yield real
3. **Simula** → testa decisões antes de executar
4. **Colabora** → compartilha com contador, sócio, consultor
5. **Reporta** → relatório profissional em 2 cliques
6. **Expande** → avalia oportunidades com contexto patrimonial

---

## Visão de longo prazo

Quando a Altora tiver patrimônio consolidado de centenas de famílias:

1. **Dados** — perfil patrimonial real de cada investidor
2. **Matching** — oferta cruzada com necessidade patrimonial
3. **Confiança** — data room, governança e histórico já existem
4. **Tokenização** — parceria ou licença quando volume justificar

Isso é **consequência** de ter o SO patrimonial, não o produto inicial.

## IP da Altora

O diferencial não é o gráfico. É o **motor patrimonial**:

```
Ativo
 ├─ tipo (imóvel, FII, CRI, PE…)
 ├─ valuation (método + data + fonte)
 ├─ fluxos (aluguel, provento, juros, capital call)
 ├─ liquidez (prazo estimado de saída)
 └─ documentos / eventos

Portfólio
 ├─ agregação por entidade / classe / região
 ├─ métricas (yield, concentração, liquidez estrutural)
 └─ snapshot para what-if e relatórios
```

Dashboards e relatórios são consequência. Poucos fazem o modelo de dados certo para alternativos brasileiros.
